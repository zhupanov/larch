# Orchestrator NEVER List

Cross-skill anti-pattern rules for single-iteration larch orchestrators. Skills should read this file when a step or recovery path explicitly references it; do not assume every skill loads it at session start.

Bgjob-migrated helpers use `skills/shared/bgjob-wait.md` as the normative wait contract.

1. **NEVER improvise ScheduleWakeup outside skill-script direction.** **Why**: single-iteration skills end at their terminal cleanup step. The orchestrator calling `ScheduleWakeup` on its own initiative, or narrating "next iteration" / "loop sleeping until ..." prose, is improvisation outside the skill's steps. Recurring behavior is owned exclusively by `/loop`'s `<<autonomous-loop-dynamic>>` sentinel mechanism — never by orchestrator improvisation in a child skill's terminal turn. **How to apply**: do not call `ScheduleWakeup` from any skill that does not have a numbered step directing the call. See AGENTS.md for the project-wide rule. **CI-backed**: yes — `scripts/test-anti-improvised-wakeup.sh` pins the literal at this site.

2. **NEVER treat a sub-skill's terminal output as the parent skill's terminal output.** **Why**: skills invoked via the Skill tool (for example `/larch:issue`, `/larch:review`, `/larch:design`) produce visually-terminal output — machine footers (`ISSUES_*`, `REVIEW_*`), sentinel writes, and human-readable summaries — that collectively read like a stopping point. Producing a summary and ending the turn after a sub-skill returns has caused observed regressions (issue #2681: `/design` Step 5b halt skipped Step 5c rename to `[DESIGNED]` after `/larch:issue` returned). The sub-skill's terminal output marks the SUB-skill's end, NOT the parent skill's. **How to apply**: when a Skill-tool sub-skill returns, immediately continue with the parent skill's NEXT numbered step (or sub-step) before producing any summary or human-readable closing prose. See `skills/design/SKILL.md` `Anti-halt continuation reminder` and the per-sub-step `Continue to Step` banners for the /design-specific application. **CI-backed**: yes — `make test-design-structure` pins the literal at this site.

3. **NEVER wait on long helpers with task-output reads, Monitor, sleeps, or ad-hoc probes.** **Why:** larch-owned bgjob daemons already provide a typed, rejoinable wait surface. A second observation channel can race the daemon result env and make the orchestrator advance on incomplete state. **How to apply:** launch long helpers through their wrapper, then use only the step's documented `scripts/larch.sh bgjob wait` invocation. After `BGJOB_STATUS=WAIT`, run the identical wait again with no intervening prose, Read, Monitor, TaskOutput, sleep, or alternate probe. After `BGJOB_STATUS=DONE`, parse the final wait stdout and `$TMPDIR/bgjob/<step>.result.env`; continue only when `BGJOB_RC=0` and the step's required KVs are present. Treat `BGJOB_RC=timeout`, `BGJOB_RC=orphaned`, any other non-zero `BGJOB_RC`, or missing required KVs as the step's failure or stall route. Do not treat compatibility sentinels, launcher stdout, or wrapper stdout as completion evidence. **CI-backed**: yes; `crates/larch-cli/tests/bgjob.rs` covers the transport, and skill harnesses pin per-step gates.

4. **NEVER reuse a stale merge-result env for a fresh bgjob start.** **Why:** a prior attempt's KVs can make a new wait look complete before the child writes its own result. **How to apply:** truncate or recreate the step's merge-input env immediately before every `bgjob start`, and pass a unique `--step` slug for each concurrent lane so logs, registry rows, and `$TMPDIR/bgjob/<step>.result.env` cannot clobber each other.

5. **NEVER treat the Step 8 ship-driver rc as a generic bgjob success or failure.** **Why:** `ship route-exit` routes through direct ship outcome KVs, not the generic `BGJOB_RC=0` success gate. **How to apply:** Step 8 reads the numeric driver rc and outcome KVs from `bgjob/implement-step8-ship.result.env`; `BGJOB_RC=timeout` or `BGJOB_RC=orphaned` still blocks as a bgjob transport failure, but a numeric driver rc is route data for the Step 8 ship flow.
